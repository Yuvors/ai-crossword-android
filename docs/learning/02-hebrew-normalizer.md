# שיעור 2: HebrewNormalizer, תווים ויוניקוד, ובדיקות יחידה

> הקוד של `HebrewNormalizer` ושל הבדיקות שלו נכתב בעזרת AI (Claude). בתיעוד של המחלקות זה מסומן במפורש, כפי שהמכוון דורש.

קבצים:
- `app/src/main/java/com/yuval/tashchetz/logic/HebrewNormalizer.java`
- `app/src/test/java/com/yuval/tashchetz/logic/HebrewNormalizerTest.java`

## הבעיה
ה-AI מחזיר תשובות כמו שכותבים אותן בעברית: "שלום", "בית ספר", "ג'ירפה", לפעמים עם ניקוד. בגריד של התשחץ:
- כל משבצת היא אות אחת, ואין סופיות (החלטה בפרויקט). "שלום" נכתב "שלומ".
- אין רווחים, גרשים או מקפים. "בית ספר" נכתב "ביתספר".
- אין ניקוד.

לפני ש-`ArrowGridGenerator` מנסה לשבץ מילה, צריך להביא אותה לצורה הזאת. אחרת "שלום" ו"שלומ" ייראו לאלגוריתם כשתי מילים שונות, וההצטלבויות לא יעבדו: ם בסוף "שלום" צריכה להיפגש עם מ בתחילת "מים".

## רקע: איך Java שומרת אותיות
ב-Java, `char` הוא מספר. כל תו בעולם קיבל מספר בטבלה שנקראת **יוניקוד** (Unicode), ו-`char` שומר את המספר הזה.

כל האותיות העבריות יושבות ברצף, מ-א (מספר `0x05D0`) עד ת (מספר `0x05EA`). הסופיות נמצאות באמצע הרצף, כל אחת מיד לפני האות הרגילה שלה:

| סופית | מספר | רגילה | מספר |
|---|---|---|---|
| ך | `05DA` | כ | `05DB` |
| ם | `05DD` | מ | `05DE` |
| ן | `05DF` | נ | `05E0` |
| ף | `05E3` | פ | `05E4` |
| ץ | `05E5` | צ | `05E6` |

הניקוד (קמץ, פתח, דגש וכו') הוא **תו נפרד** שבא אחרי האות. "שָׁ" הם שלושה תווים: ש, שין-דוט, קמץ. כל סימני הניקוד וטעמי המקרא יושבים בטווח `0x0591`–`0x05C7`. בתוך הטווח הזה יש גם את המקף העברי (־).

מכיוון ש-`char` הוא מספר, אפשר להשוות תווים עם `<` ו-`>`:
```java
public static boolean isHebrewLetter(char c) {
    return c >= FIRST_LETTER && c <= LAST_LETTER;   // 'א' עד 'ת'
}
```

## הקוד, פעולה אחרי פעולה

### מחלקת עזר
```java
public final class HebrewNormalizer {
    private HebrewNormalizer() {
    }
    ...
}
```
- כל הפעולות `static`: הן לא צריכות שום מצב (אין שדות שמשתנים), רק קלט ופלט. קוראים להן כך: `HebrewNormalizer.normalize("שלום")`.
- **בנאי פרטי**: אי אפשר לכתוב `new HebrewNormalizer()`. אין טעם ליצור עצם ממחלקה שאין לה מצב.
- `final`: אי אפשר לרשת ממנה.

זו אותה תבנית כמו `Math` ב-Java (`Math.max`, `Math.abs`).

### `toRegular`: סופית → רגילה
```java
public static char toRegular(char c) {
    switch (c) {
        case 'ם':
            return 'מ';
        ...
        default:
            return c;
    }
}
```
`switch` על `char` בוחר מקרה לפי התו. כל תו שאינו סופית מגיע ל-`default` וחוזר כמו שהוא.

אפשר היה לכתוב את זה גם כ-`return (char) (c + 1);`, כי כל סופית נמצאת מספר אחד לפני הרגילה. בחרנו ב-`switch` כי הוא ברור יותר בקריאה, וכי הטריק הזה היה נשבר לו מישהו היה מעביר אות שאינה סופית.

הפעולה ציבורית כי גם מסך המשחק ישתמש בה: אם המשתמש מקליד ם במקלדת, בגריד ייכתב מ.

### `normalize`: הפעולה המרכזית
```java
public static String normalize(String text) {
    if (text == null) {
        return "";
    }
    StringBuilder result = new StringBuilder();
    for (int i = 0; i < text.length(); i++) {
        char c = text.charAt(i);
        if (isHebrewLetter(c)) {
            result.append(toRegular(c));
        }
    }
    return result.toString();
}
```
עוברים על התווים אחד-אחד. אות עברית → מוסיפים את הצורה הרגילה שלה. כל תו אחר (ניקוד, רווח, גרש) פשוט לא נכנס.

**למה `StringBuilder` ולא `result = result + c`?** מחרוזת (`String`) ב-Java היא **בלתי ניתנת לשינוי** (immutable). כל `+` יוצר מחרוזת חדשה ומעתיק אליה את כל התווים. בלולאה, זה הרבה העתקות מיותרות. `StringBuilder` הוא מחרוזת שאפשר לשנות במקום, ובסוף ממירים אותה ל-`String` פעם אחת.

### `isValidAnswer`: פסילת תשובות פגומות
ל-`normalize` יש חולשה: היא מוחקת **כל** מה שאינו אות עברית. אם ה-AI מחזיר "שלום1" או "הtest", היא תחזיר "שלומ" או "ה", והאלגוריתם ישבץ מילה שגויה בלי לדעת.

לכן יש פעולה שנייה, שבודקת את התשובה **לפני** הנרמול:
```java
public static boolean isValidAnswer(String text) {
    ...
    for (...) {
        if (isHebrewLetter(c)) {
            letterCount++;
        } else if (!isIgnorable(c)) {
            return false;          // ספרה, אות לועזית וכו'
        }
    }
    return letterCount >= MIN_ANSWER_LENGTH;
}
```
- תו שהוא אות → סופרים.
- תו שמותר למחוק (ניקוד, רווח, גרש, מקף) → ממשיכים.
- כל תו אחר → התשובה נפסלת מיד.
- בסוף, תשובה עם פחות משתי אותיות נפסלת, כי בתשחץ אין מילים של אות אחת.

ההפרדה בין שתי הפעולות היא החלטה מכוונת: **`isValidAnswer` מחליטה אם לקבל, ו-`normalize` ממירה.** כך הסדר ב-`ArrowGridGenerator` יהיה: קודם בודקים, ורק תשובה תקינה מנרמלים.

## מגבלה ידועה
מחיקת הגרש משנה את ההגייה: "ג'ירפה" נכתב "גירפה", ו"צ'יפס" נכתב "ציפס". זה המקובל בתשחצים בעברית, ולכן זה בסדר. ראשי תיבות כמו "צה"ל" הופכים ל"צהל", וגם זה מקובל.

## בדיקות יחידה (Unit Tests)
בדיקת יחידה היא קוד שבודק קוד אחר: קוראים לפעולה עם קלט ידוע ומוודאים שחוזר הפלט הצפוי. משתמשים בספרייה **JUnit**:

```java
@Test
public void normalize_turnsFinalLettersToRegular() {
    assertEquals("שלומ", HebrewNormalizer.normalize("שלום"));
}
```
- `@Test` מסמן פעולה כבדיקה. JUnit מריץ כל פעולה כזאת בנפרד.
- `assertEquals(expected, actual)`: אם הערכים שונים, הבדיקה נכשלת ומודפס מה היה צפוי ומה התקבל.
- `assertTrue` / `assertFalse`: לתנאים.
- שם הבדיקה אומר מה נבדק: `פעולה_מה-אמור-לקרות`.

**למה זה אפשרי בלי אמולטור?** כי `HebrewNormalizer` כתובה ב-Java נקי, בלי שום מחלקה של אנדרואיד. זו בדיוק הסיבה שהפרדנו את `logic/` מ-`ui/`. בדיקות כאלה יושבות ב-`app/src/test` ורצות ישירות על המחשב, תוך שניות.

> מצב נוכחי: עוד אין קבצי Gradle, ולכן Android Studio עוד לא יודע להריץ את הבדיקות. הן הורצו פעם אחת ידנית עם JDK 17, ו-10 מתוך 10 עברו. אחרי שיתווסף `build.gradle` (עם `testImplementation 'junit:junit:4.13.2'`) יהיה אפשר להריץ אותן בלחיצה ימנית → Run.

## שאלות שבוחן עשוי לשאול
1. **למה צריך את `HebrewNormalizer`?**
   כדי שכל מילה תיכתב בגריד באותה צורה: בלי סופיות, ניקוד או רווחים. אחרת הצטלבויות בין מילים לא יתאימו.
2. **איך בודקים אם תו הוא אות עברית?**
   `char` הוא מספר ביוניקוד. האותיות העבריות ברצף, מ-א עד ת, אז בודקים `c >= 'א' && c <= 'ת'`.
3. **למה הפעולות `static`, ולמה הבנאי פרטי?**
   אין למחלקה מצב, אז אין צורך בעצם. הבנאי הפרטי מונע יצירת עצם בטעות.
4. **מה ההבדל בין `String` ל-`StringBuilder`?**
   `String` לא משתנה, וכל `+` יוצר מחרוזת חדשה. `StringBuilder` משתנה במקום, ולכן יעיל בלולאה.
5. **למה יש גם `isValidAnswer` ולא רק `normalize`?**
   `normalize` מוחקת בשקט כל תו לא מוכר, כך שמילה פגומה מה-AI הייתה נכנסת לגריד. `isValidAnswer` פוסלת אותה לפני כן.
6. **מה זו בדיקת יחידה, ולמה היא יכולה לרוץ בלי אמולטור?**
   קוד שבודק פעולה אחת עם קלט ופלט ידועים. היא רצה בלי אמולטור כי המחלקה לא תלויה באנדרואיד.
7. **שינוי שבוחן עשוי לבקש:** "תגרום לכך שגם ספרות יימחקו ולא יפסלו." → להוסיף את הספרות ל-`IGNORED_SYMBOLS`, או להוסיף ב-`isIgnorable` את התנאי `Character.isDigit(c)`.
